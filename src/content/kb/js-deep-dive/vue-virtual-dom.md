# Vue 虚拟 DOM 详解

在现代前端开发中，虚拟 DOM（Virtual DOM）是许多主流框架的核心基石。Vue 通过虚拟 DOM 实现了声明式渲染、跨平台开发，并在保证开发体验的同时提供了极高的性能下限。

本文将从 VNode 的本质、渲染器（Renderer）核心机制、Diff 算法细节以及 Vue 3 的编译时优化等维度，彻底解析 Vue 虚拟 DOM 的内部工作原理。

---

## 1. 虚拟 DOM 与 VNode 的本质

### 1.1 为什么需要虚拟 DOM？
真实 DOM（Document Object Model）非常庞大，包含上百个属性。频繁、无节制地直接操作真实 DOM，不仅代码繁琐，还会导致浏览器频繁触发**重排（Reflow）**与**重绘（Repaint）**，引发严重的性能卡顿。

虚拟 DOM 用轻量级的 JavaScript 对象来描述真实的 DOM 结构。当状态发生改变时，我们先在 JavaScript 中计算出虚拟 DOM 的变化，最后集中对真实 DOM 进行一次性最小化更新。

> [!NOTE]
> 虚拟 DOM 不一定比纯手工的极简 DOM 操作更快。它的核心价值在于：**在不用手动优化 DOM 的前提下，为任意复杂的应用提供“足够好”的性能下限，并为跨平台渲染（如 SSR、小程序、Canvas、Native App）提供了可能。**

### 1.2 什么是 VNode？
在 Vue 源码中，虚拟 DOM 节点的最小单位是 VNode（Virtual Node）对象。

一个简化的 VNode 数据结构如下：
```typescript
interface VNode {
  type: string | object | symbol; // 节点类型：如 'div'、组件对象、Fragment 等
  props: Record<string, any> | null; // 属性：如 class、id、eventListener 等
  children: VNode[] | string | null; // 子节点：子 VNode 数组或纯文本
  el: HostNode | null; // 对应的真实 DOM 节点引用
  key: string | number | symbol | null; // 唯一标识，用于 Diff 算法的性能优化
  shapeFlag: number; // 快速标识节点类型的位掩码（如是普通元素还是组件）
  patchFlag: number; // 编译时生成的动态标记，用于靶向更新
}
```

在日常开发中，我们编写的 `<template>` 模板在打包时会被编译器转换为渲染函数，运行该渲染函数就会生成这一系列的 VNode 节点树。

## 2. 渲染器的挂载与更新流程

渲染器（Renderer）是虚拟 DOM 系统的灵魂，负责将 VNode 渲染成特定平台上的真实元素。其核心入口函数是 `patch`。

### 2.1 挂载阶段（Mount）
当旧的 VNode 为空时，渲染器直接根据新 VNode 创建真实 DOM：
1. **创建元素**：利用宿主平台 API（如 `document.createElement`）创建真实 DOM 节点。
2. **处理属性**：将 VNode 的 `props` 绑定到新元素上。
3. **递归子节点**：若 `children` 是数组，则递归调用 `patch` 挂载每个子节点。
4. **插入 DOM**：将创建好的元素挂载到父节点中，并把真实 DOM 引用保存到 `VNode.el` 上。

### 2.2 更新阶段（Patch）
当新旧 VNode 同时存在时，`patch` 会进入更新比对阶段：
- **同类型节点比对**：若新旧 VNode 的 `type` 和 `key` 相同，则调用 `patchElement` 仅对比并更新它们不同的属性与子节点。
- **不同类型节点替换**：若类型不同，则直接销毁旧 DOM 节点，重新挂载全新的新节点。

## 3. 核心 Diff 算法剖析

当新旧节点的子节点都是数组时，为了最小化 DOM 的创建和移动操作，渲染器会启动核心的 **Diff 算法** 进行子节点更新。

### 3.1 为什么需要 key？
如果列表节点没有 `key`，Vue 会默认采用“就地复用”策略：仅仅按照顺序简单对比。如果列表发生了位置交换，Vue 会直接修改每个节点上的内容，而不是移动 DOM 元素本身。

而带上唯一的 `key` 之后，Vue 就可以精准建立 VNode 与真实 DOM 的映射关系，通过移动已有 DOM 节点完成更新，极大地提升了更新效率与安全性。

### 3.2 有 key 的双端对比 5 步法
在 Vue 3 中，有 `key` 的子节点更新使用了一套非常高效的双端 Diff 算法。它的比对步骤分为以下五个阶段：

#### 第一步：自前向后比对（Sync from start）
从新旧列表的头部开始向后比对，只要 `key` 和 `type` 相同就进行 `patch` 复用，一旦遇到不同节点则停止。

#### 第二步：自后向前比对（Sync from end）
从新旧列表的尾部开始向前比对，只要 `key` 和 `type` 相同就进行 `patch` 复用，一旦遇到不同节点则停止。

#### 第三步：挂载新增节点
如果在前两步比对结束后：
- 旧列表的指针已经超出了边界（旧节点比对完了）。
- 新列表的指针内还有剩余节点。
代表新指针范围内的节点全部是新插入的，渲染器会将它们依次挂载到 DOM 中。

#### 第四步：卸载多余节点
同理，如果在比对结束后：
- 新列表的指针已经超出了边界（新节点比对完了）。
- 旧列表的指针内还有剩余节点。
代表旧指针范围内的节点在新的 DOM 中已被删除，渲染器会循环将其依次卸载。

#### 第五步：比对乱序节点（最长递增子序列）
如果比对完首尾，新旧列表内部都剩下了未比对的“乱序”节点，这是 Diff 最核心也是最复杂的阶段：

1. **建立映射表**：遍历新列表剩余节点，建立一个 `key -> 新列表索引` 的 Map。
2. **填充数据源数组**：建立一个长度等于新剩余节点数量的数组 `source`，用来记录新节点在旧列表中的位置索引。默认填充 `-1`（代表是新增节点）。
3. **遍历旧节点，标记复用**：遍历旧列表中剩余的节点，利用第一步的 Map 查找其在新列表中的位置。
   - 找不到：说明该旧节点已被删除，直接卸载。
   - 找到了：说明节点可复用，计算新位置，并在 `source` 中填入其在旧列表的旧索引。同时 `patch` 复用该节点属性。
4. **移动节点（引入 LIS 算法）**：
   - 寻找 `source` 数组中的**最长递增子序列（Longest Increasing Subsequence, 简称 LIS）**。
   - 最长递增子序列代表了**在更新前后，相对顺序没有改变的子节点序列**。
   - 在移动节点时，凡是处于最长递增子序列中的节点，**在 DOM 中保持不动**。仅移动不在该子序列中的乱序节点，从而实现 DOM 移动次数的最小化。

## 4. Vue 3 编译时优化

虚拟 DOM 的一大痛点在于：即使模板中 90% 的内容是静态的，在运行时依然需要递归遍历整棵虚拟 DOM 树进行 Diff 比对，造成了不必要的性能浪费。

Vue 3 引入了「编译时与运行时结合」的优化方案，让虚拟 DOM 运行时的性能大幅逼近原生的静态模板。

### 4.1 静态提升（HoistStatic）
编译器在解析模板时，如果发现某个节点及其子节点完全是静态的（没有任何动态绑定或事件），就会将其**提升**到渲染函数外部声明。

#### 优化前（伪代码）
```javascript
function render() {
  return createVNode("div", null, [
    createVNode("span", null, "我是一个静态文本"), // 每次 render 都会重新创建 VNode
    createVNode("p", null, ctx.dynamicText)
  ])
}
```

#### 优化后（伪代码）
```javascript
const hoisted_span = createVNode("span", null, "我是一个静态文本"); // 仅创建一次

function render() {
  return createVNode("div", null, [
    hoisted_span, // 运行期直接复用引用，零内存与 CPU 开销
    createVNode("p", null, ctx.dynamicText)
  ])
}
```

### 4.2 属性静态标记（PatchFlags）
编译器在生成动态节点 VNode 时，会在其最后一个参数中注入一个数字标记——`patchFlag`（即动态标记）。

例如：
```javascript
createVNode("p", { class: "static-class", id: ctx.dynamicId }, null, 8 /* PROPS */, ["id"])
```

这里的 `8` 就是一个代表「仅具有动态 props 属性」的 PatchFlag。当更新发生时，更新引擎看到这个标记，会**直接跳过 Class、子节点、文本等其他内容的对比**，靶向对比 `id` 属性即可。

常见 PatchFlags 的位掩码：
- `1` (TEXT): 动态文本。
- `2` (CLASS): 动态 Class。
- `4` (STYLE): 动态 Style。
- `8` (PROPS): 动态属性（如 `id`、`name` 等，会额外记录动态属性名数组）。
- `-1` (HOISTED): 静态提升的节点（Diff 时直接跳过）。

### 4.3 区块树（Block Tree）
在常规的树形 Diff 中，需要一层层比对节点。而 Block Tree 允许我们将一个含有动态节点的组件模板「压平」。

当模板中含有 `v-if` 或 `v-for` 时，编译器会将其内部拆分为不同的 **Block（区块）**。每一个 Block 会在根节点上维护一个 `dynamicChildren` 数组，里面直接线性收集了该 Block 下所有的**动态子节点**。

当组件更新时，渲染器**不再需要递归整棵树**，而是直接沿着当前 Block 的 `dynamicChildren` 数组进行一维的线性 Diff。所有的静态结构都会被完全忽略，这就使得 Diff 算法的性能只与**动态节点的数量**相关，而与**模板的总大小**无关。

## 5. 虚拟 DOM 选型优缺点总结

虚拟 DOM 的权衡艺术：

| 维度 | 优势 | 局限性 |
| :--- | :--- | :--- |
| **开发效率** | 声明式编程模式，无需繁琐的命令式 DOM 修改代码，维护体验极佳。 | 学习曲线较长，需依赖工具链对渲染函数和模板进行处理。 |
| **运行性能** | 在复杂应用中提供平稳的性能曲线，有效避免开发者因编写低效 DOM 操作而导致页面卡顿。 | 对于结构极度简单、数据变动频繁的局域节点更新，相比原生精细化 DOM 操作会有轻微的框架额外开销。 |
| **平台拓展** | 虚拟 DOM 的抽象层脱离了浏览器宿主，使得代码能轻易运行在服务器端（SSR）、小程序或跨平台移动端。 | 在需要调用平台特定底层接口或极其苛刻的性能场景（如超大型 3D 渲染画布）下仍需退回到真实环境。 |

Vue 3 渲染系统的真正魅力，正是通过「编译时优化」与「高效运行时双端 Diff」的双剑合璧，既保留了虚拟 DOM 带来的极致开发效率与跨平台表现，又在性能上追平乃至超越了无虚拟 DOM 的纯编译框架。
