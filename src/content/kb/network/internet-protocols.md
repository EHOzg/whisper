# 互联网协议与底层网络构造

计算机网络是现代数字世界的基础设施。要真正理解网络，我们需要将其拆解为分层的协议栈，并观察数据是如何在每一层被封装、传输和解析的。

### 核心分层模型

在实际开发与设计中，我们通常结合 **OSI 七层模型**与 **TCP/IP 四层/五层模型**来理解网络结构：

* **应用层（Application Layer）**：直接为用户进程提供服务，例如 HTTP、DNS、FTP、SMTP。
* **传输层（Transport Layer）**：负责端到端（Port to Port）的通信，确保数据的可靠或高效传输。核心协议是 TCP 与 UDP。
* **网络层（Network Layer）**：负责主机到主机（Host to Host）的寻址和路由选择。核心协议是 IP，以及路由选择协议如 OSPF、BGP。
* **数据链路层与物理层（Link & Physical Layer）**：负责相邻节点之间的物理传输（通过网线、光纤或无线信道），传输单位为帧（Frame）与比特（Bit）。

### 传输层双雄：TCP 与 UDP

#### 1. TCP（传输控制协议）
TCP 是一种**面向连接的、可靠的、基于字节流**的传输层协议。它通过一系列复杂的机制保证数据不丢失、不重复、不乱序。

* **三次握手（Three-way Handshake）**：建立连接时，确保双方的发送与接收能力正常。
* **四次挥手（Four-way Teardown）**：释放连接时，双方分别通知对方关闭发送通道，确保所有待发送的数据都已传输完毕。
* **可靠性保证**：校验和、序列号与确认应答（ACK）、超时重传、流量控制（滑动窗口）以及拥塞控制。

#### 2. UDP（用户数据报协议）
UDP 是一种**无连接的、不可靠的、基于数据报**的传输协议。

* **特点**：没有拥塞控制，不保证送达，首部开销小（仅 8 字节，TCP 至少 20 字节）。
* **适用场景**：视频会议、在线游戏、DNS 查询等对实时性要求极高、允许少量丢包的场景。

### 应用层皇冠：HTTP 协议的演进

HTTP 协议是现代 Web 的基石，它的演进历史也是一部网络性能优化的历史：

* **HTTP/1.1**：引入了持久连接（Keep-Alive）和管道化（Pipelining），但存在**队头阻塞（Head-of-Line Blocking）**问题。
* **HTTP/2**：引入了**多路复用（Multiplexing）**、头部压缩（HPACK）和服务器推送（Server Push），允许在同一个 TCP 连接上并发处理多个请求，解决了 HTTP 层的队头阻塞。
* **HTTP/3 (QUIC)**：为了解决 TCP 底层的队头阻塞问题（当发生丢包时，整个 TCP 连接会被阻塞），HTTP/3 放弃了 TCP，转而基于 **UDP** 实现了 **QUIC** 协议。它在应用层实现了可靠传输、快速连接建立（1-RTT 或 0-RTT）以及连接迁移。
